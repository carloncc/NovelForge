# 生成界面（动线 / 流程 / 布局）重构方案

> 目标：让「导入小说 → 生成 → 预览 → 导出」成为一条直路。生成页不再让用户在三条互斥路线里做选择，也不再把「分章生成」藏在门槛后面。
> 本文是 P0 分析结论与总计划；验收标准与逐条验证证据见 `.specs/tasks/done/generate-flow-refactor.feature.md`。

## 一、现状诊断（全部有据可查）

生成页 `src/pages/GeneratePage.vue` 单文件 3650 行（`<script setup>` 1–2899 行、`<template>` 2901–3670 行），185 个顶层声明，`execute()` 单函数约 250 行。问题不是"按钮丑"，而是**信息架构把一条直线拆成了迷宫**。

### 1. 三条互斥路线 + 页面随路线变形（动线问题的根）

- `runMode` 三选一（`:2931-2933` 整书生成 / 单阶段重跑 / 单章节生成），选中后**整页下半部分换掉**：整书面板 `:3065`、阶段盘 `:3121`、单章盘 `:3158` 是三套互斥布局。
- 顶部主按钮的**文案和语义随模式漂移**：单章模式下从「开始生成」变成「顺序生成未完成」（`:2904-2907`），`start()` 内部再分支到 `runChapterQueue()` 或 `execute()`（`:1365-1375`）。同一个位置、同一个按钮，做两件完全不同的事——这就是"绕弯道"的来源。
- 模式被持久化并自动选中（`:81-90`）：老用户再次进入会被直接丢进某个模式，而不知道还有别的路线。

### 2. 「分章生成」存在，但被埋、被锁、且不完整

- 想生成单章，必须先切到单章模式 → 点「AI 分章预览」→ 点「确认分章」→ 才能逐章点「生成本章」（`:3172`、`:3173`、`:3186-3195`）。
- 队列有**硬门槛**：没有历史结果又未显式确认分章时直接报错拒绝（`:439-442`）。
- 单章链**不含配音**（`:1713` 只跑 `script/image/assemble`，`:3198` 文案承认），所以"分章生成"产不出完整一章。
- 单章链**隐式依赖角色卡**：没有卡片时直接报错要求先跑提取阶段（`:1691-1694`），但界面上没有把这一步串进流程。
- 还有**第二套章节选择 UI**：整书模式里的章节勾选网格（`:3100-3119`，用 `rerunChapters`）与单章模式的 `ChapterStatusBoard`（用 `chapterForce/feedback`）语义不同、行为不同。同名同事、两套控件。

### 3. 选项面重复、互相解释

- `useImage` 同时出现在「生成内容」（`:2953`）和单阶段级联面板（`:3142`），后者的 tooltip 写着"与上方是同一个"——需要靠文案解释的重复控件就是模型错了。
- `useTts` 同样重复（`:2972` 与 `:3145`）。
- 阶段选择也有两份：整书模式的阶段勾选（`:3073-3078`）与单阶段模式的 `StageStatusBoard`（`:3128`）。
- 「高级设置」把 CG 上限 / 图像上限 / 种子藏在折叠里（`:3031-3062`），而生成内容主区又平铺了 8 个开关。

### 4. 结果区：8 个 tab 混装运行与内容

`:3214-3230` 一口气排了 状态与费用 / 失败项 / 日志 / 素材 / 卡片编辑 / 剧本 / 视觉守门 / 视频推荐位。其中「日志」还是靠末尾 `v-else` 兜底（`:3643`）。素材 tab 内部再套 5 个子 tab（`:3304-3310`）和几十个单项重生成按钮。运行态（进行中的进度）与产物编辑（素材/剧本）被平级塞进同一排，用户不知道该看哪一块。

### 5. 空态把用户支走去别的页面

`:3202-3210` 有三段几乎同义的"还没有小说 / 还没有结果"，全是纯文字指路，没有就地可点的动作。

### 6. 结构债已经产生过事故

状态、IO、渲染全挤在一个组件里，所以最近一次修复叫「按钮联动与并发安全修复（队列锁定/运行期禁切项目/关闭图像时章节完成判定/全选含服装）」（`cae1345`）。按钮联动要靠事后补丁，说明状态没有单一来源。

## 二、目标信息架构

一条主线，四段结构，从上到下：

```
生成项目
[1] 项目栏    输出目录 / 浏览 / 加载该项目 / 状态徽章（章节 字数 素材 运行状态）
[2] 生成内容  图像 表情 动作 三视图 配音 BGM 视频位 资料卡 | 语言 画风 剧本风格 参考图 | 高级设置
[3] 生成      范围：[逐章] [整本] [单阶段]   ← 只切换这一块，不换整页
              逐章工作台（默认）工具栏：AI 分章 / 全选未完成 / 生成选中(N) / 顺序补全 / 追加新章 / 含配音
                                   每章一行：状态灯 意见 全量 生成本章 停用
[4] 结果      状态与费用 · 素材 · 剧本 · 卡片 · 视觉守门 · 视频 · 失败项 · 日志
```

### 硬性规则

1. **主按钮唯一且语义固定**：每个范围面板内自带主操作按钮，文案只描述本范围要做的事；页面顶部不再放一个会变身的按钮。
2. **章节是一等公民**：默认范围＝逐章（有小说时）。
3. **分章不设卡**：未分章时就地提供 AI 分章；分章结果只是可核对的信息与一个提示徽章，不再阻塞生成。
4. **单章可独立完成**：单章链支持可选配音，并就地处理缺角色卡的前置，不靠报错让人自己找路。
5. **一个开关只有一个地方**：级联面板只显示状态，不再重复绑定 `useImage` / `useTts`。
6. **空态给动作**：单一提示 + 就地按钮，不再三段同义指路。

## 四、非目标

- 不改管线语义（分章 / 提取 / 剧本 / 图像 / 配音 / 组装 的算法不动）。
- 不改导出与预览页。
- 不追求一次性重写全部 2900 行脚本；先让页面结构正确，再逐步下沉状态。

## 实施结果（已完成）

本方案已落地，任务单见 `.specs/tasks/done/generate-flow-refactor.feature.md`（含逐条 AC 的验证证据与偏差说明）。

- 生成页重构为四段：项目栏 -> 生成内容 -> 生成（范围切换 + 当前范围面板）-> 结果；范围切换只替换第三段。
- 「逐章生成」成为默认范围；章节工作台支持单章 / 多选批量 / 顺序补全 / 追加新章 / 逐章意见与全量 / 可选含配音，
  且不再有「确认分章」硬门槛（分章状态退化为徽章与可核对信息）。
- 同一语义选项只出现一次：级联面板里的 `useImage` / `useTts` 复选框改为只读状态显示。
- 结果 tab 按「运行 / 产物」分组，`v-else` 兜底日志 tab 已改为显式 `v-else-if`。
- 代码结构（最终）：`GeneratePage.vue` 3722 -> 369 行，页面只保留四段编排、逐章分支与结果宿主；
  区块组件在 `src/components/generate/`：`ProjectBar.vue` / `OptionsPanel.vue` / `ScopeTabs.vue` /
  `ChapterWorkbench.vue` / `FullRunPanel.vue` / `StageRunPanel.vue` / `ResultSection.vue`。
- 状态与行为：`src/stores/generate.ts` 为模块级单例（191 个绑定，运行态单一来源）；页面与各区块组件都经
  `useGenerateController()` 取用同一份状态，因此范围选择、结果 tab 在离开生成页再回来时仍然保留。
  导航状态独立为 `src/stores/nav.ts`。
- 结果区 `ResultSection.vue` 承载 8 个 tab 的全部面板及其模板 ref（`logPanelRef` / `videoInput`），
  按「运行 / 产物」两组渲染，原先靠末尾 `v-else` 兜底的日志 tab 已改为显式 `v-else-if`。

### 有意未做（非遗漏）

- `src/stores/generate.ts` 仍是一个模块（3163 行），但内部已按域分成清晰小节（生成范围 / 分阶段状态 /
  逐章工作台 / 素材重生成 / 保真核对）。再拆成 `useChapterWorkbench` / `useAssetRegen` /
  `useScriptVerify` 属于纯机械搬移且需要共享闭包上下文；在 UI 目标已达成的前提下收益低于回归风险，
  故保留现状。
- 结果区的素材 / 剧本 / 视频 / 失败四个面板仍内联在 `ResultSection.vue`。若要继续，建议按这四个内聚边界拆，
  而不是按卡片位置拆（同为纯搬移，可零行为变更地继续）。
