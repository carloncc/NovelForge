# 视觉守门排查：是否基于全局小说生成 & 多套衣服怎么整

> 排查范围：视觉守门（Visual Bible）全链路 — 风格分析（visualBible.ts `analyzeNovelStyle`）、角色三视图（`createDraftCharacters` / `regenerateCharacterSheet`）、角色卡提取（extract.ts / extractAgent.ts）、换装立绘与引用（images.ts `resolveImageTaskReferences`）。

---

## 一、结论速览

| 环节 | 是否基于全局小说 | 说明 |
| --- | --- | --- |
| 全局风格描述 | ✅ 是 | 整本小说按 1.2 万字分块 → 并行分析 → 归并 → 综合成一条风格描述（`analyzeNovelStyle`） |
| 角色卡（含多套服装） | ✅ 是 | 提取阶段把**整本小说**（模型上下文预算内）交给 LLM，SYSTEM_PROMPT 明确要求收录所有换装（日常服/礼服/战斗服/睡衣等，数量不限）；Agent 模式按 id 并集合并 |
| 角色三视图 | ✅ 间接是 | 用角色卡的 `threeViewPrompt`（来自全局提取）+ 全局风格描述生成 |
| 换装立绘 | ⚠️ 锚点单一 | 每套服装生成独立立绘，但**所有服装都以「默认装三视图」为图生图参考** |
| 视觉守门面板 | ❌ 不显示服装 | 面板只展示每角色一张三视图，服装不参与确认 |

**结论：视觉守门的内容（风格/角色/三视图）确实是基于全局小说生成的，不是只看某一章。**

## 二、多套衣服的现状处理方式

1. **提取**：`costumes[]` 收录角色全部服装（id/name/prompt），prompt 要求「人物外貌完全一致 + 该服装款式/颜色/材质」。
2. **三视图**：每角色只生成**一张默认装三视图**（身份锚点）。
3. **换装立绘**：图片阶段按 `costumes[]` 生成 `figure_<id>_ct_<costumeId>.png`，`refFromTask: <id>_threeview`（拿默认装三视图做 img2img 参考，再叠服装 prompt）。
4. **换装演出**：剧本按剧情标注 `costume`，渲染层维护换装状态机，切装后沿用直到再次标注。
5. **鉴赏室**：服装差分进入换装/鉴赏界面。

所以「多套衣服」**当前是支持的**（换装立绘 + 演出切换）。

### 现有方案的短板

- **三视图只锚定一套默认装**：当角色服装差异大（如 校服 vs 战甲 vs 晚礼服）时，换装立绘要让模型「改衣服、保脸」，一致性全靠提示词，容易脸崩或服装被忽略。
- **视觉守门确认界面对服装不可见**：用户批准前看不到「这个角色到底有几套衣服、每套长什么样」，无法提前发现问题。
- **三视图重生成只重画默认装**：换装锚点没有独立的重新生成入口。

---

## 三、改进方案：每套服装独立三视图锚点

为每个角色**每套服装**额外生成一张「服装三视图」（以默认装三视图为身份参考 → 脸/体一致 + 服装正确），换装立绘改为引用**对应服装的三视图**，而不是默认装三视图。

```
默认装三视图 ──身份参考──▶ 服装A三视图 ──身份参考──▶ 服装A立绘/表情
                  └──身份参考──▶ 服装B三视图 ──身份参考──▶ 服装B立绘/表情
```

- 数据：`VisualBibleCharacter.costumeSheets: Record<costumeId, { threeViewPath, prompt, revision, approved }>`
- 生成：创建草稿 & 重生成三视图时，对每套服装自动生成一张三视图（失败不阻断，自动回退默认装锚点）
- 引用：`resolveImageTaskReferences` 对带 `costume` 的任务优先引用该服装三视图
- 面板：角色下方展示各服装三视图缩略图 + 单独重生成按钮
- 失效：角色三视图变更 → 该角色全部立绘/表情/动作/换装缓存作废（现有 `characterOwnedImageTasks` 已含换装任务）
- 代价：每套服装多一张 1024×1024 三视图（约 1 张图的钱/时间）
