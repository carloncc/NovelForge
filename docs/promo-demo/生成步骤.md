3. 页面最上方是「**项目与分章**」卡片：
   - 在「**输出目录**」输入框里填：

   - 点右边的「**加载该项目**」。

## 第 1 步：导入小说，只保留第 1 / 4 / 8 章

### 1.1 导入

1. 左侧栏 **准备 → 导入小说**。
2. 点右上角「**选择小说 txt（可多选）**」（如果已经导入过小说，按钮会变成「**重新导入**」）。
3. 选这个文件（**只选这一个**，不要多选）：
   ```
   D:\Desktop\project_my\NovelForge - Agent\小说\铁皮城堡.txt
   ```

**「分章方式」选什么？** —— **没有这个选项，不用选。**
导入页副标题写得很清楚：「单文件按标题规则初切，多文件合并为单章，生成时由 AI 重新分章」。
即：单文件导入时会用**纯正则**自动切章。本次已实测 ✅ 该正则把《铁皮城堡》切得完全正确：

- **识别出 8 章**，标题与正文一一对应，无空章、无串章、无「第一卷」误判（详见附录 A）。
- 页面「**章节（单文件按标题规则初切…）**」表格会列出 8 行，列是：**启用 / 标题 / 字数 / 段落数**。
- 标题可以直接在表格里改（点标题输入框改名）。

### 1.2 只保留第 1 / 4 / 8 章 —— 取消勾选另外 5 章

在同一个章节表格里，把「**启用**」列的勾去掉这 5 行：

| 保留 | 取消勾选（停用） |
|---|---|
| 第一章 墙在敲、第四章 不能开灯、第八章 第九声 | 第二章、第三章、第五章、第六章、第七章 |

每取消一个，会弹确认框：

> 「停用第 N 章「标题」后，后续 M 个启用章节编号前移，已有剧本/配音缓存会按新编号重新对齐（可能触发重配）。继续吗？」

点「**确定**」。5 个都点一遍。

> **为什么用「停用」而不是在生成页只勾 3 章？**
> 两条路都能得到 3 章游戏（实测渲染器会把启用章重新编号成 0/1/2，`changeScene:ch1→ch2→ch3` 连续，
> 见附录 A 末尾），但**停用更省图**：只勾 3 章时另外 5 章会被记为「缺剧本章节」，
> 代码在这种情况下**不会**把「剧本实际用到的表情/动作」写回卡片
> （`src/core/pipeline.ts:2508`），出图端就退回卡片全量 → 多出十几张永远不上屏的差分。
> 停用则完全不产生这个副作用，组装时也不会打「渐进式组装：N 个章节暂无剧本」的警告。

### 1.3 看一眼分章状态

回到 **制作 → 生成项目**，顶部「**章节**」旁边会出现标签：

- 「**待核对分章**」= 还没核对；「**分章已核对**」= 已核对。
- 旁边还有分章来源文字（本次导入后应显示为**导入规则切分**，不是 AI 分章）。

**本步要不要点「AI 分章」？—— 不要点。**
- 那个按钮（在「项目与分章」卡片里，「分章意见」输入框右边）会**强制全书 AI 重新分章，计费**，
  并作废下游剧本/图像/配音缓存。本次 8 章已被正则切得完全正确，没有理由花这笔钱。
- 点它旁边的「**标记为已核对**」，标签变成「分章已核对」即可（只是本地标记，不计费）。
- 提示文案也确认了这一点：「填了意见会强制全书 AI 重新分章（计费），并作废下游剧本/图像/配音缓存」。

## 第 2 步：生成设置（关掉 3 个、打开 2 个）

左侧栏 **准备 → 生成设置**。页面有 5 个 tab：**内容 / 立绘 / 输出与质量 / 分章 / 项目**。

### 2.1 【必须改】AI 抠图 —— 在「API 配置」页，不在生成设置页

⚠️ **这个开关不在生成设置里，在 左侧栏 准备 → API 配置 页最下方「AI 抠图模型」区块。**

| 控件 | 选项 | 本次选 |
|---|---|---|
| **抠图方式** | `AI 抠图优先（失败自动降级色度键）` / `只用色度键（无需下载模型）` / `不抠图（保留原图）` | **`只用色度键（无需下载模型）`** |

**为什么**：AI 抠图模型（`isnet-anime`）**本机未下载**（`%APPDATA%\com.novelforge.app\models\` 是空的，
只有一个 0 字节的断点残留）。选 `AI 抠图优先` 会先失败再降级，日志里刷一堆错。
而 `只用色度键` 是**纯本地算法、不需要模型**，而且 NovelForge 给立绘/物品/三视图的提示词里
**强制写了纯绿幕背景**（`chroma key green background`，`src/core/images.ts` 的立绘/物品/三视图分支），
所以色度键抠图能正常抠出透明底立绘。

> 不要选「不抠图（保留原图）」：那样立绘会带着**一片绿底**进游戏，非常难看。
> 「抠图模型」下拉框在选「只用色度键」后会变灰，不用管。
> 「下载模型」按钮本次不点（需要联网下载数十 MB，且宣传 demo 用不上）。

## 第 3 步：生成（3 章）

**制作 → 生成项目**。任务区顶部有三个范围 tab：**逐章生成 / 整书生成 / 单阶段重跑**。

逐章生成要求**先有角色/场景/物品卡**，否则会显示提示：「还缺角色 / 场景 / 物品卡 —— 逐章生成需要先有卡片」。
所以第 3 步分 3.1 + 3.2 两小步。

### 3.1 先只跑「提取」，把卡片拿到手

1. 切到「**整书生成**」tab。
2. 「**本次执行阶段**」勾选网格里（顺序是 **分章 / 翻译 / 提取 / 剧本 / 图像 / 配音 / 组装**）：
   - **取消勾选「分章」** ⬅ 关键。本次 8 章已由导入规则切好，不勾分章就**不会**调用 AI 重新分章
     （源码 `src/core/pipeline.ts:1775-1796`：章节已切好且未勾分章时只读缓存元数据，不发 LLM 请求）。
   - **取消勾选「翻译」**。
   - **只勾「提取」**。
3. 「**章节范围**」不用动（提取是**全书级**一次调用，会读全部 8 章正文 —— 停用章节不影响提取，
   所以卡片里会包含全书人物，这对宣传 demo 是好事）。
4. 点主按钮「**开始生成**」。

预计耗时：**1 ~ 3 分钟**。费用：一次提取调用，约 0.0x 元量级。

> ⚠️ **不要点「逐章生成」面板里的「先提取卡片」按钮**。那个按钮跑的是 `分章 + 提取` 两阶段
> （源码 `stores/generate.ts:818-823`），会**连带触发 AI 全书重新分章（计费）并作废下游缓存**。
> 用上面的「整书生成 → 只勾提取」这条路。

### 3.2 逐章生成 3 章

1. 切回「**逐章生成**」tab。
2. 工具栏（这一行是：`含配音` 勾选框 · `已选 N / M` · `重跑选中 ▾` · 主按钮）：
   - **勾上「含配音」** ⬅ 勾了才会把该章台词一起配音（提示：「会产生 TTS 费用」）。
   - 主按钮此时写着「**补全未完成**」（因为还没勾章节）。
3. 章节列表里，勾选**那 3 行没有被淡化的**（「已停用」的 5 行是灰的，不需要也不应该勾）：
   - 第一章 墙在敲 / 第四章 不能开灯 / 第八章 第九声。
4. 勾完 3 行后，工具栏计数变成「**已选 3 / 8**」，主按钮文案自动变成「**生成选中**」。
5. 点「**生成选中**」。
6. 弹确认框：「将逐章生成 3 个章节，含配音（TTS 计费）……剧本/图像按缓存只补缺失（已完成的不会重复计费）。继续吗？」
   → 点「**确定**」。
7. 之后每章还会各弹一次单章确认（「第 N 章「标题」全链开始……」）—— 逐章链路是**一章跑完再跑下一章**，
   中途失败/中止会停下来。

**会跑哪些阶段**（逐章链实际组合，源码 `stores/generate.ts:2666-2669`）：

```
剧本 → 图像 → 配音 → 组装        （每章一轮；「含配音」已勾）
```

- **分章**：不跑（3.1 也没跑）—— 导入时的正则分章结果直接沿用，0 费用。
- **提取**：不在逐章链里（3.1 已经跑过了）。
- **剧本 / 图像 / 配音 / 组装**：每章一轮，共 3 轮。
- 组装是**本地操作、不计费**，每章跑完都会刷新一次预览。

预计耗时：**15 ~ 40 分钟**（图像并发 30，配音逐句）。费用：见开头总账。

> **想一次跑完、少点几下？** 也可以全程用「整书生成」：
> 勾上 `提取 + 剧本 + 图像 + 配音 + 组装`（不勾分章/翻译）→ 章节范围保持默认（启用章即 3 章）
> → 点「开始生成」。一次跑通，行为等价。本文按任务要求以「逐章生成」为主线写。

## 第 4 步：验收（看 4 个指标）

跑的过程中，生成页顶部有吸顶进度卡（阶段名 + 百分比 + 「进度：done/total · step」）；
下面结果区有 5 个 tab：**运行 / 产物 / 设定 / 视觉守门 / 日志**。

### 4.1 章节灯（逐章生成面板里每行的状态标签）

每行右侧一个标签，口径是（源码 `ChapterWorkbench.vue:67-74`）：

| 标签 | 含义 | 怎么办 |
|---|---|---|
| `未生成` | 还没剧本 | 勾上它再点「生成选中」 |
| `缺图 x/y` | 该章 y 张图只出了 x 张 | 去「运行」tab 看失败项；或在「重跑选中 ▾ → 重跑图像」 |
| `缺配音 x/y` | 该章 y 句配音只出了 x 句 | 「重跑选中 ▾ → 重跑配音」 |
| `旧缓存` | 旧版剧本缓存无指纹，图像数按旧剧本估 | 建议对该章「重跑剧本」 |
| `已完成` | 剧本齐、图齐、配音齐 | ✅ 目标状态 |
| `失败` | 该章剧本失败 | 见 4.3 |

面板里还有一行「**图片统计：** 图片共 N 张：已生成 X · 待生成 Y」。

### 4.2 「运行」tab 的统计卡

- 顶部 4 个数字：**章节**（应显示 **3**）/ **总字数** / **素材** / **状态**（`已完成` / `有失败项` / `运行中`）。
- 「**用量统计（本次运行）**」：LLM / 图像 / 配音 三项费用 —— 这就是本次实际花掉的钱。
  **拿它和本文开头的估算对一下**（图像应落在 63~69 张 × 0.3 元附近）。

### 4.3 失败项怎么重试

AI 提取时会把老焊/苏医生/小满这类配角标成 `isNpc`（→ S3），
若没标则按全主要角色（→ S2）。

### B.2 配音

```
配音句数   225 句（其中 145 句旁白）
逐角色      narrator 145 · 沈岩 73 · 小满 4 · 老焊 2 · 阿禾 1
合成字符数 4111 字
平均每句   18.3 字；最长一句 118 字（< 单句上限 205，不会被拆段）
费用       4111 / 1,000,000 × 500 = 2.0555 元
```

> 配音便宜得可以忽略（2 元）。**主要开销在图像**。
> 真实句数取决于 AI 剧本的行粒度，本文的 225 句是按「引号句 + 段落」启发式拆的，
> 实际可能落在 **150 ~ 350 句**区间；即便如此，配音费用也只有 **1.4 ~ 3.2 元**。

### B.3 抠图的影响

「不抠图 / 色度键 / AI 抠图」**不改变出图张数**（它是出图后的本地后处理），
所以对上面的张数与费用没有影响。它只影响立绘是否带透明通道：
- `只用色度键`（推荐）：本地算法，透明底，无额外费用。
- `不抠图`：立绘保留绿幕背景，游戏里会看到一片绿。
- `AI 抠图优先`：本机模型未下载 → 先失败再降级，日志刷错。
