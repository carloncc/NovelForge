## ① tests/stage-runner.ts 的真实能力（结论：**跑不了整部小说**）

支持的 stage（`stage-runner.ts:7-9, 464-466`）：
`split | translate | extract | script | image | recutout | assemble | all | baseline`，
其中 `all = split,translate,extract,script,image,recutout,assemble`（TTS 不跑），`baseline = split,translate,extract,script`（默认）。

**它写死了小说、章节范围、输出目录、gameKey：**

| 位置 | 写死内容 |
|---|---|
| `stage-runner.ts:13, 65` | 分章输入 = 内置示例小说 `DEMO_NOVEL`（不是任意小说） |
| `stage-runner.ts:120` | 提取输入 = `DEMO_NOVEL`，标题写死 `"星陨之城的守夜人"` |
| `stage-runner.ts:147` | 剧本**只跑第 1 章**（注释原文「只跑第 1 章以控时」） |
| `stage-runner.ts:165` | 只写 `script-ch1.json` |
| `stage-runner.ts:172, 191` | 图像只读 ch1 剧本，`generateImages(..., [script], ...)` 只传 1 章 |
| `stage-runner.ts:374, 383, 385` | 组装 `outputDir` 写死 `tests/.tmp-stage-runner/output`，`gameKey` 写死 `starfall-night-watch`，`chapters: [script]` 只有 1 章 |
| `stage-runner.ts:77, 111, 135, 143, 165, 176` | 中间产物目录写死 `tests/.tmp-stage-runner/*` |

**没有任何 CLI 参数或环境变量能改这些**——`process.argv[2]` 只用来选 stage（`stage-runner.ts:447`）。
所以 `all` 的产物是「内置示例小说的 1 章 WebGAL」，**不是《铁皮城堡》8 章**；而且它完全没有 TTS 阶段。

## ② config.json 真实结构（**不含任何 key 值**）

```
%APPDATA%\com.novelforge.app\config.json
├─ configSchemaVersion
├─ presets                 ← 数组，本机 1 个元素（不是对象）
│   └─ [0]
│       ├─ id, name
│       ├─ active        { llm: "<channelId>", vision: "...", image: "...", tts: "..." }
│       └─ channels
│           ├─ llm    [ { id, name, baseUrl, model, extra{discoveredModels,contextLength}, concurrency } ]
│           ├─ vision [ { id, name, baseUrl, model, extra{...} } ]
│           ├─ image  [ { id, baseUrl, model, extra{...}, concurrency }, { id, baseUrl, model, adapter:"minimax-image", ... } ]  ← 2 个
│           └─ tts    [ { id, baseUrl, model, adapter:"minimax-tts", extra{voiceLibrary(311 项),...} } ]
├─ activePresetId, outputDir, recentOutputDirs, projects, voiceProfiles, cutout
```

**`apiKey` 字段在文件里完全不存在**（已确认，key 在 Windows 凭据库）。

**最小内联密钥写法**：在**当前激活的那个通道对象**上加 `apiKey`：

```
presets[0].channels.<llm|vision|image|tts>[ i ].apiKey = "<key>"
其中 i 满足 channels.<kind>[i].id === presets[0].active.<kind>（找不到 active 时退化为 [0]）
```

这与 `stage-runner.ts:40-45` 的读取口径完全一致（`list.find(c => c.id === activeId) ?? list[0]`）。
注意 `channels.image` 有 2 个元素，**必须注入 active 指向的那个**（本机 active=`82syi3is`，即 `[0]`）。

## ③ 脚本做了什么

`pwsh -File "…\宣传demo\生成全部.ps1"`：

1. **备份** `config.json` → `config.json.nfbak`（逐字节），记录原始 SHA-256。
2. **不回显读 4 个 key**：`Read-Host -AsSecureString`（llm/vision/image/tts），直接回车=跳过。
   明文只经 `Marshal::PtrToStringBSTR` 进内存，用后 `ZeroFreeBSTR` + 置 null + `GC.Collect()`。
3. **内联注入** active 通道；写回用 `UTF8Encoding($false)`（**无 BOM**，否则 Node 的 `JSON.parse` 会挂）。
   全程只打印「已注入 llm, vision, image, tts」，**绝不打印 key 值**。
4. **写标记文件** `config.json.nfrunning` 后才改配置 → 之后任何崩溃，下次启动自动用备份还原。
5. **跑全量**：`node <repo>\node_modules\tsx\dist\cli.mjs 宣传demo\full-run.mts`
   → `Pipeline`：提取 →（视觉守门自签）→ 剧本 → 图像 → 配音 → 组装，全部 8 章。
6. **finally 无条件还原**：先用随机字节覆盖 `config.json`（尽量不留明文），再从 `.nfbak` 还原，
   校验 SHA-256 与原始一致并打印；删除标记文件。Ctrl+C 也会走 `finally`。
