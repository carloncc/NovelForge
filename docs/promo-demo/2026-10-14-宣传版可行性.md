## B. 不走 AI 的备用路径可行性

### B.1 demo 模式**不能**用于自定义小说 —— 有源码级确证

demo 判定口径（三处完全一致）：

- `src/core/pipeline.ts:1750` — `const demo = !input.llm?.apiKey;`
- `src/core/pipeline.ts:1717` — `demo: !input.llm?.apiKey,`
- `src/core/project.ts:52-55` — 注释明说「口径与 pipeline（`const demo = !input.llm?.apiKey`）、stores/generate 完全一致」

即：**只要文本通道没有 apiKey，整条管线就进 demo 分支**。而 demo 分支的数据源是写死的：

- `src/core/extract.ts:265-266`：
  ```ts
  /** demo 卡片为内置固定数据，与传入正文无关（`_novelText` 仅为与真实提取同签名）。 */
  export function demoExtract(_novelText: string, title: string): ExtractionResult {
  ```
  → 参数名是 `_novelText`，**完全未使用**。返回的角色固定为「林澈 / 苏晚晴 / 老铁匠 / 店小二」（`src/core/extract.ts:267-332`），场景/物品同理写死。
- `src/core/pipeline.ts:1896-1897`（增量）与 `src/core/pipeline.ts:1965-1966`（全量）：
  ```ts
  cards = demo ? demoExtract(workingNovel.fullText, this.titleFor()) : ...
  ```
  → 把自定义小说全文**传进去然后被丢掉**。
- `src/core/pipeline.ts:2245-2246`：
  ```ts
  script = demo ? demoScriptAll([chapter], cards!)[0] : ...
  ```
- `src/core/script.ts:1450-1452`：`demoScriptAll` 只是逐章调用 `demoScriptChapter(c, cards)`，**数据源仍是那套写死的卡片**。
- 内置示例小说本体：`src/core/demoNovel.ts:1` `DEMO_NOVEL`（「星陨之城的守夜人」，3 章）。
- `DEMO_NOVEL` 在整个 `src/` 中**只有 demoNovel.ts 一处引用**，没有任何"用自定义小说替换"的开关。

**结论：无 key 时，《铁皮城堡》会得到一套"林澈/苏晚晴"的卡片和剧本 —— 角色、场景、台词与小说完全无关。demo 模式是产品演示用的固定样例，不是"无 key 降级生成"。**

  const f=path.join(root,p);
  if(!f.startsWith(root)){res.writeHead(403);return res.end();}

    res.writeHead(200,{'Content-Type':mt[path.extname(f).toLowerCase()]||'application/octet-stream'});
