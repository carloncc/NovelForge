# AI 生成剧本 vs 真实 Galgame：文字显示差距分析

> 分析对象：NovelForge 当前 AI 剧本生成（src/core/script.ts）→ 渲染（src/core/render.ts）→ WebGAL 引擎（src-tauri/templates/webgal）全链路。
> 结论先行：**差距是真实存在、可复现、可代码定位的**。它不在某一步，而是「生成内容 → 渲染逻辑 → 引擎排版」三层叠加的结果。

---

## 一、差距全景

| 层面 | AI 生成现状 | 真实 Galgame 惯例 |
| --- | --- | --- |
| 说话人 | 台词有时被「旁白化」，无姓名框 | 对话必带姓名框（nameplate） |
| 动作/引语 | 「他叹了口气：」独立成旁白行，句末留逗号 | 靠立绘/表情/演出表现，或作为舞台提示（斜体/居中） |
| 消息粒度 | 一条消息 = 一整段（自动换行） | 每条消息 1~3 行，编剧手动断行，一屏一句 |
| 内心独白 | 与旁白视觉完全一致 | 常以斜体/特殊颜色/「」区分 |
| 台词语言 | 保留小说原文（偏长、偏文、多铺垫） | 短句、口语、可念白、有角色口癖 |
| 姓名 | 显示角色卡全名 | 常用简称/昵称 + 称号 |
| 资料卡 | 首次登场把整段外貌/性格塞进旁白 | 独立角色资料界面，或干脆不显示 |

---

## 二、证据（均在代码/实跑中定位）

### 证据 1：台词被「旁白化」——说话人名牌丢失（最直观的“显示差距”）

用示例小说跑 demo 流程，第一章渲染结果（tests/_probe-render.ts 输出）为：

```
:林澈，城门要关了，回去歇着吧。;      ← 老铁匠对林澈说，却显示成旁白（无姓名）
:林澈大人，许久不见。;               ← 苏晚晴的台词，显示成旁白
:这一带最近总有妖兽出没的踪迹。;      ← 林澈的台词，显示成旁白
:老铁匠叹了口气：;                   ← 动作描写独立成行
:林澈微微皱眉：;                     ← 动作描写独立成行
:她的声音温柔，却在暮色里透着一丝忧虑，;  ← 描写句，以逗号结尾
```

**根因**：
- demo/无 API 兜底用 parseParagraph（script.ts L329）靠“人名是否出现在引号前 14 字内 / 引号后跟说话动词”来猜说话人；猜不到就 emitNarration，台词直接变旁白。示例里“林澈，城门要关了”这句引号前没有“老铁匠”字样，于是归不进对话。
- LLM 正式路径也有同样风险：scriptChapter 对缺失 characterId 的 dialogue 回退到 cards.characters[0]?.id（第一个角色），且项目专门写了 verifyScriptAgainstSource（script.ts L580）来检测 context-mismatch / third-person-self / not-in-source / order-suspect——这就是“AI 说话人经常张冠李戴”的官方确认。

玩家看到的结果：本该有姓名框的台词变成一段无主旁白，这是“文字显示”上最明显的不对劲。

### 证据 2：动作描写/引语标签被拆成独立旁白行

上面输出里的「老铁匠叹了口气：」「林澈微微皱眉：」都来自原文的“某某说/某某动作 + 引号句”。真实 galgame 几乎不会把“X叹了口气：”单独显示成一行旁白——动作靠立绘表情/演出传达，对话直接进姓名框。AI 输出这种“旁白 + 逗号结尾”的碎片行，观感很“小说朗读”而非“galgame”。

### 证据 3：一条消息 = 一整段，没有手动断行

render.ts 的 esc()（L38-48）把文本里的换行**全部压成空格**：

```ts
function esc(text: string): string {
  return (text || "")
    .replace(/\\/g, "\\\\")
    .replace(/[;.,:`]/g, "\\$&")
    .replace(/\r?\n/g, " ");   // ← 换行直接变空格
}
```

而 WebGAL 引擎本身**支持**换行（引擎源码中按 /(?:\r\n|\r|\n)/ 拆分文本测量行宽），也支持超长文本自动分页。结果：AI 输出的一整段（可能 3~6 句）在游戏里就是**一个自动换行的长段落**，玩家一次点击要读一大块，节奏与“一屏一句、一句一页”的 galgame 体感完全不同。

更关键的是：**渲染链路里没有“按句读断行/限长”的后处理**（grep 整个 pipeline/render 均无分句逻辑），所以段落长短完全交给 LLM 的即兴发挥。

### 证据 4：内心独白与旁白视觉不区分

render.ts 里 narration 和 monologue 都渲染成：

```ts
out.push(`:${esc(line.text)}${narVocalArg};`);
```

没有给独白任何字体/颜色/引号标记。真实 galgame 常用斜体、特殊颜色或「」把“内心想法”和“客观叙述”分开，是代入感的重要来源。

### 证据 5：人物资料卡整段塞进旁白

首次登场时渲染成（render.ts L233 起）：

```
:【林澈】 黑色短发，眼神锐利，身材修长，面容冷峻 沉默寡言，重情重义，背负着守护城池的使命;
```

一整段外貌+性格平铺成旁白。真实 galgame 要么有独立角色资料界面，要么根本不弹这种“设定说明书”。

### 证据 6：姓名用全称

对话渲染为「角色全名:台词;」（如 老铁匠:你和你爹一样……;）。真实 galgame 姓名框常用简称/昵称（樱月、优斗之类）并配合称号，更短更“角色感”。

### 证据 7：引擎排版（文本框样式未完全主题化）

- WebGAL 默认正文框（._TextBox_main_p1zxt_18）是浅蓝渐变底、高 330px、字重 700、字距 0.2em、左侧大头像大圆角。
- NovelForge 的 game/userStyleSheet.css 覆盖了 GlobalDialog 等组件，但**没有覆盖 ._TextBox_main_p1zxt_18 / ._TextBox_Background_p1zxt_43**（实测正文白色 25.6px、资源圆体、黑底——黑底来自 GlobalDialog 覆盖，但整体排版仍是引擎默认）。
- 也就是说整套界面是“暗色玻璃拟态”，唯独正文框沿用了 WebGAL 默认骨架，风格有轻微割裂。

## 三、根因归纳

1. **“忠实原文”约束与 galgame 语言冲突**：系统提示词强制“原文「」内对话一句不许删”，于是台词是**小说语言**（长句、书面、多叙事铺垫），而不是为“配音 + 一屏一句”设计的**galgame 语言**。
2. **小说 → 分镜的说话人推断天然易错**：原文对话归属靠人名/动词启发式，LLM 也会错，出错就是“旁白化/张冠李戴”，这是显示上最刺眼的一类。
3. **渲染层把结构化信息扁平化**：动作（action）、情绪（emotion）、独白（monologue）、资料卡全是结构化字段，但渲染时几乎都落成普通旁白文本行，丢掉 galgame 靠“演出 + 排版”承载信息的习惯。
4. **没有导演级后处理**：断行、句读节奏、消息长度上限、姓名框短名、独白样式——这些“让文字像 galgame”的加工环节在管线里是缺失的。

---

## 四、改进建议（按性价比排序）

1. **渲染层按句读断行（最高性价比，直接改善“显示文字”）**：对旁白/对话在 esc() 前按句子长度插入换行，让每条消息 1~3 行；并给长消息按句切分为多条 WebGAL 消息（每次点击一句），立刻有“一句一页”的节奏。
2. **说话人归属增强**：parseParagraph 与 verify 的启发式增加“冒号前是动作描写 + 后续引号句”的合并（把「他叹了口气：」与下一句引号合并为 dialogue 并推断说话人），减少旁白化。
3. **动作标签独立样式**：把「X说/道/叹气：」这类句子识别为舞台提示，用 WebGAL 文本样式（斜体/居中/不同颜色）呈现，而不是普通旁白。
4. **独白视觉区分**：给 monologue 加字体/颜色/引号标记。
5. **姓名框短名**：用角色卡的简称字段或取姓名后 2~3 字。
6. **角色资料卡独立界面**：新增角色资料页（WebGAL 有对应 UI 能力），或精简为一行。
7. **Prompt 增加 galgame 风格约束**：对话短句化、口语化、每句可念白、减少叙事性铺垫；旁白也用短句断行。

> 第 1、2、3 项只改 render.ts / script.ts，不碰引擎与模板，落地成本最低、对“文字显示”体感提升最大。

---

## 五、如何复现

- 静态：tests/_probe-render.ts 打印 demo 渲染出的 game/scene/ch1.txt（含上述旁白化台词）。
- 实跑：把模板 src-tauri/templates/webgal 拷出 → 写入 game/scene/start.txt + chN.txt 与 config.txt → 静态服务器打开 → 进游戏即看到“无姓名旁白 + 整段长文 + 资料卡平铺”的显示效果。
